# 云账号自助平台

员工在一个地方完成：看自己有哪些云账号和权限、申请开账号、申请云账号权限、申请临时访问凭证、
查看云账号资产。管理员在另一套页面里处理名册、执行失败的申请和审计。面板和 `delivery` CLI
共用同一个后端，规则只写一份。

代码在 `src/delivery/`，部署见 [deploy/panel/README.md](../deploy/panel/README.md)。

## 1. 不能退让的规则

| # | 规则 | 落在哪里 |
|---|---|---|
| R1 | **任何开通、授权、发凭证，都必须有一条已通过的飞书审批。** 执行前后端实时查飞书审批实例，状态是 `APPROVED`、审批定义、发起人、表单里的申请单号都对得上才执行；不信回调内容、不信本地状态 | `approval.py` `verify_approved()`；`flows.py` 的 execute / claim 都先调它 |
| R2 | 员工只能给自己申请：权限申请的目标子账号必须是名册里已确认属于本人的号 | `flows.py` 提交时校验 |
| R3 | 申请只能从管理员预先定义的模板里选（用户组、角色、时长上限），用户不能提交任意策略、角色 ARN、用户组名 | `catalog.py` |
| R4 | 访问凭证不落盘：临时凭证在员工领取时现签现发，只返回给本人，不写申请单、不写日志。初始密码只能在开通后 7 天内领取一次，且子账号必须是这张申请单新建、名册里没有对应给别人 | `flows.py` `claim_credential()` / `claim_password()` |
| R5 | 执行身份最小权限：只有开号、加组、移出组、扮演模板角色这几个动作，每次写云前核对凭证属于目标云账号。目前从面板服务器的环境变量读取；改用 ECS 实例角色是后续项 | `provision.py`、部署文档 |
| R6 | 员工身份只认 `feishu_union_id`（公司 IAM 规范） | 登录层（飞书 / oauth2-proxy） |
| R7 | 所有状态变化记审计：谁、何时、对哪张申请单、做了什么；审计只追加 | `tickets.py` 事件表 |

## 2. 角色

| 角色 | 能看到 | 能做 |
|---|---|---|
| 员工 | 我的云账号与权限、我的申请、我能领取的凭证、我所在云账号的资产概况 | 提交申请、撤回自己未审批的申请、领取已批准的凭证和初始密码 |
| 管理员 | 全员名册、全部申请、全部资产、审计 | 名册审核、重试执行失败的申请、关闭申请、维护模板 |

管理员名单只按 union_id（`identity/admins.json`）。**管理员自己提交的申请同样走飞书审批**，
管理员身份不能跳过 R1。

## 3. 申请类型

| 类型 | 员工填写 | 审批通过后执行 | 员工领取 |
|---|---|---|---|
| 开账号 `account` | 模板（哪个云账号、默认加入哪些组）、希望的用户名、用途 | 建子账号、加入模板里的用户组、写入人工对应（名册下次刷新生效） | 控制台初始密码（一次性，强制首次登录改密）|
| 云账号权限 `permission` | 模板（如「OSS 只读」）、目标子账号（只能选自己的）、用途、时长 | 把子账号加入模板的用户组 | — |
| 访问凭证 `credential` | 模板（对应一个受限角色）、用途、有效期 | 标记为可领取，直到有效期结束 | STS 临时凭证，每次领取现签，最长按模板上限 |

有时长的权限到期后由 `delivery requests sweep` 移出用户组。开通前子账号本来就在的组、同一子账号还有别的未到期申请给的组，都不移出。
「本来就在」只在第一次开通时判断，且不包括别的申请单加进去的组：到期前续期、开通失败后重试，都不会让限时权限变成永久。

申请页每一项都标出对本人的状态：可申请、已拥有（权限快照里子账号已在全部用户组，可续期）、
申请中、可领取、不可申请（附原因）。「已拥有」只是提示，快照没有或没采全时按「未知」显示为可申请。
模板可选填 `category`（如「存储」「AI 训练」），只用于申请页分类筛选，不影响开通内容，改分类也不影响审批中的申请。

## 4. 申请单状态

```
提交 ──► 待审批 ──► 已通过 ──► 执行中 ──► 已完成
          │           │           │
          ├► 已拒绝    │           └► 执行失败 ──(管理员重试)──► 执行中
          └► 已撤回    └► （凭证类）可领取 ──► 已过期
                                  已完成（权限类到期）──► 已到期回收
```

- 状态只能按上图流转，其他转换一律拒绝。
- 「开通中」「提交中」超过 30 分钟没有进展视为中断，标成失败，由管理员核对后重试或关闭。
- 飞书里通过后又被撤销（实例 `reverted`）的审批，一律按未通过处理。
- 「已通过」只由同步飞书审批状态得到；同步可以是员工或管理员打开申请单，或 `delivery requests sweep`
  定时任务——都只是「去飞书查一次」，结论以飞书接口返回为准。

## 5. 组件

```
浏览器 / delivery CLI
        │  （飞书登录或公司 IAM，经 oauth2-proxy）
        ▼
server.py ── HTTP 接口、角色校验、CSRF
   ├─ tickets.py    申请单：状态机、存储、审计
   ├─ catalog.py    模板目录（identity/request-templates.json）
   ├─ approval.py   飞书审批：发起、查询、校验
   ├─ provision.py  执行器：阿里云 / 火山的开号、加组、STS
   ├─ flows.py      申请流程（面板和 CLI 共用）
   ├─ requests_api.py 申请接口与员工视角裁剪
   ├─ assets.py     云账号资产（资源中心）
   ├─ views.py      权限页面数据（员工视角 / 管理员视角分开）
   └─ review.py     名册审核
```

数据文件都在 gitignored 的 `identity/`，0600：

| 文件 | 内容 |
|---|---|
| `tickets.json` | 申请单与审计事件 |
| `request-templates.json` | 模板目录（示例：`identity/request-templates.example.json`）|
| `approval.json` | 飞书审批定义编号与表单控件 ID（示例：`identity/approval.example.json`）|
| `assets.json` | 资产快照 |

## 6. 开源件怎么用

| 环节 | 用什么 | 为什么不自己写 |
|---|---|---|
| 登录 | oauth2-proxy + 公司 IAM | OIDC 细节多，成熟件更安全 |
| 审批 | 飞书审批 | 审批记录、审批人配置、移动端都现成 |
| CLI 里调云 | 官方 `aliyun` / `ve` CLI | `delivery creds` 只负责给它们提供临时凭证，不重写各云命令 |
| 签名调用 | 仓库内零依赖实现（已有） | 仓库硬规定不引运行时依赖 |
